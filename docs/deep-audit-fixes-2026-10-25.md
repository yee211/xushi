## 其他问题

- 小程序登录写入与鉴权读取使用相同代际缓存键。
- 追问保存独立的更新时间，以最后一轮交互计算 15 分钟有效期，保留原问题时间。
- “不要同步/取消同步”不再识别为同步进度查询。
- 单对象查询纠正后，后续成功可以覆盖此前对象解析错误；显式多对象请求保留独立失败，不被其他人的成功掩盖。
- 对话式开场后已有具体课程事实的回复不再被等待正则误杀；真正等待、稍后回复等承诺仍被拦截。
- 整周查询的学期外占位数据携带预期课表 ID，修复同步后续查询的边界校验。
- 同学整周比较跳过学期外日期，并在结果中说明未参与比较的日期；全部不可得时不宣称课表一致。
- 同学名单加载失败不再阻断自己的课程查询。
- “未来 7 天”限制为含今天在内的 7 个自然日；规则解析支持“明早”。
- 单周调课与批量调课统一锁定所属课表，串行检查幂等键；真实数据库并发测试覆盖重复提交。
- Web、小程序请求与上传正确展开 FastAPI 422 校验数组。
- 小程序自动重登录后，同学页仍能解除旧请求的 loading 状态；旧会话结果不写入新会话。
- 小程序导入后刷新失败会明确提示，避免按旧课表报告导入数量。
- 已有的备用课表学期设置/删除入口恢复可达；学校课表保持现有的设置限制；反馈入口恢复显示。
- 数据库初始化名称取自配置，默认统一为 xushi_schedule。
- Compose 使用分离的 PG 参数传递数据库密码；连接池、Alembic 和备份工具均支持，避免 URI 特殊字符破坏连接。
- 数据挂载为空或不可用时仍保留数据库备份，并在完整备份包中写入缺失标记与告警。
- GitHub 发布前检查版本文件已提交；已有 Tag 核验提交并重试推送；任一附件上传失败立即停止，不进入历史 Release 清理。
- pg_restore 使用 --if-exists 和 --single-transaction，URI 用户名/密码正确解码。
- 教务 resume 容忍文件系统 OSError，避免整个 API 因维护恢复失败而无法启动。
- 教务目录缺失专业列表时保留旧目录；不再以通用“暂无数据”文本认定班级学生列表完整为空。

## 部署要点

1. 更新 API 前应用迁移 `0026_auth_revocation`。容器启动命令已执行 Alembic，直接运行 API 的部署需主动升级。
2. JWT 校验新增数据库吊销时间检查，需要可用的数据库连接。
3. 对照实际代理/Docker 网关设置 `TRUSTED_PROXY_CIDRS`，边缘代理覆盖 XFF；默认仅信任回环地址。
4. 旧教务 Profile 没有账号归属证明时会被清理，需要管理员重新完成学校登录。换号以后旧环境 Cookie 不再可用。
5. 持续失败的微信消息保留重试并暂停本批次游标，需要根据错误日志修复原因；不再通过丢弃消息推进进度。
6. 新增或私网 LLM 地址需配置 `LLM_ALLOWED_BASE_URLS`；更换地址需显式提交相应 Key。
7. 发布脚本在本地构建产生待提交文件时停止 GitHub 发布，提交已验证产物后使用现有 `--publish-github` 入口发布。
