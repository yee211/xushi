# 学生课表查询模块

已实现网页 / Android 共用弹窗、微信小程序独立页，以及 FastAPI 查询接口。
这是一份只读学校课表查询；查询结果独立于用户自己的 schedules 数据。

## 运行配置

1. 按现有管理后台说明配置 ADMIN_USERNAME、ADMIN_PASSWORD、ADMIN_SESSION_SECRET。
   ADMIN_SESSION_SECRET 至少 32 字符。
2. 用学校账号在浏览器登录教务，超级管理员在序时 /admin 的“学校教务连接”页
   填入该浏览器教务请求中的 Cookie 与 User-Agent，点击“验证并保存连接”。
3. 普通用户登录序时后，网页 / Android 操作菜单点击“查同学课表”；
   小程序首页点击“查同学课表”，选择年级并输入姓名或班级。
4. 学校会话过期后，管理员重新登录学校并更新连接配置。

当前版本采用管理员手动维护已有学校会话。未实现学校账号密码直接登录或自动续期。
本机尚未配置管理后台密钥，因此没有持久保存调查时的学校登录会话。
也可以通过进程环境 CCSUT_COOKIE、CCSUT_USER_AGENT 提供连接；
管理员保存的加密配置优先于环境配置。

配置加密保存在 server/data/academic/connection.enc；
Docker 中为 /app/data/academic/connection.enc，现有 data 挂载会保留该文件。
该目录被 Git 忽略，不包含在提交中。更换 ADMIN_SESSION_SECRET 后需重新连接。

## 查询与完整性

学生姓名、班级、显示学号来自正常学生列表；学号保留学校返回的脱敏值。
同名学生提供多个候选项，用户选择后查询，编码标识不作为序时身份认证凭据。

首次查询先取得整学期报表和真实校历，再遍历该学期所有校历周次核验 JSON。
成功后显示已核验周数与同步时间；以逐周结果作为课程数据。
两份来源不一致时显示提示。报表有课程而逐周接口全部为空时返回错误。
空周的已观察接口契约是 ret=0 且无 data；请求失败和未知数据结构不视为空周。
任何失败周或无效课程字段均不发布新的完整快照。

报表 HTML 的自动换行、单双周、课程地点变化和连续节次解析位于
server/app/html_parser.py，WebView 导入与后台查询共用。
学校直连使用精确数据模式，保留真实单节，不推测补齐下一节。

缓存包含最多 128 份完整课表和 5000 个已查询学生，保存到
server/data/academic/cache.sqlite3。15 分钟内复用内存结果；重启后可以
读取持久缓存，连接过期时显示上一份完整课表、原同步时间和失败原因。
会话更新保留学生选择上下文和持久缓存。年级、学生搜索和学期入口支持
离线回退；离线学生搜索只覆盖之前查过的学生，不代表全校目录。
查询总时间上限为 60 秒，核验采用串行限制。当前适用于单服务器部署，
多个服务器实例需要共享数据库；缓存目录含学生资料，仅供服务运行账户访问。

第一版没有全校历史学期批量抓取或自动通知。会话维护与首次登录操作见
[会话维护说明](academic-session-renewal.md)，后台显示维护进程最近检查状态。

## 接口

查询接口使用现有序时用户鉴权，管理连接仅允许超级管理员。
- GET /api/academic/students?grade=2024&name=...&class_name=...
- GET /api/academic/students/{id}/terms
- GET /api/admin/academic/connection
- PUT /api/admin/academic/connection，正文 cookie / user_agent

学校登录过期返回业务状态 connection_expired，不触发序时用户重新登录。
管理接口不返回 Cookie 或加密原文。报表临时签名只用于当次同域请求。
服务端拒绝向其他域名发送学校凭据。

## 已完成验证

2026-10-08，通过当前学校会话验证独立 httpx 客户端可读取目录和报表。
本人及同班另一名学生的报表，各得到 33 条合并课程安排，
按星期、节次、周次、课程、教师、教室展开后均与逐周 JSON 的 348 个记录完全一致。
这不等于验证全校所有学生的所有历史学期。

实际 API 链路验证：按姓名 / 班级找到本人，读取 5 个已发布学期，
查询当前学期返回 complete=true、20/20 周、report_matched=true；
第二次查询命中缓存。
浏览器使用匿名样例验证搜索、选择学生、学期和课表结果交互。
网页构建和小程序模板、JavaScript 语法检查通过；小程序未在微信开发者工具实机验证。


## 学校身份绑定

网页与 Android 的入口位于「我的 → 学校身份绑定」。选择年级，输入专业、
班级或姓名的部分文字，点击候选学生后确认绑定。每个序时账号保存一名学生，
可解除绑定后重新选择。绑定保存于 PostgreSQL academic_bindings，不因 Cookie
轮换或服务重启丢失。绑定页面保留课表学期选择和同步操作。
接口 GET / PUT / DELETE /api/academic/binding，PUT 正文 student_id。
绑定选择只用于课表关联，不用于证明该学生身份或授予管理权限。

## 完整学生目录与本地搜索

管理后台「课表同步 → 学生目录 → 刷新完整学生名单」提交后台任务。
服务按年级、班级采集完整名单，沿用学校 HTTP 请求限流，不受搜索结果 100 人上限限制。
进度、最近成功时间和错误信息在后台显示。任务保存在 PostgreSQL，多进程通过
数据库锁保证单个采集器执行，服务重启后会重新执行未完成任务。

完整采集成功后，在同一事务中替换 PostgreSQL 学生目录；采集或写入失败保留旧名单。
首次同步成功前使用原学校实时搜索；同步后身份搜索和年级入口直接查询本地目录，
学校登录过期也可搜索和绑定。搜索最多返回 100 个候选；课表仍通过学校接口查询。
当前目录由管理员手动刷新，尚未加入定时刷新或 Redis 搜索缓存。

迁移 0015_academic_directory 新建目录与控制表；应用启动也幂等创建。
多进程部署仍须配置共享 Redis，以协调所有学校请求的限流。
可通过 ACADEMIC_DIRECTORY_WORKER_ENABLED=false 停止当前进程的目录采集器；
至少一个服务进程需要启用采集器才能处理刷新任务。

数据库测试使用独立临时 schema，模拟学校数据，不访问学校：
`TEST_ACADEMIC_DIRECTORY_DB=1` 后运行 `test_academic_directory_db.py`。
