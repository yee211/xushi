# Agent 澄清与继续执行

缺少会影响查询结果的信息时，模型使用 `needs_input` 提出一个具体问题；信息充分时直接查询。纯澄清问题不要求先调用查课工具，仍校验不受依据支持的课程、同步状态或未来工作承诺。

待确认问题使用独立 Redis 状态，保存原问题、追问及最多三轮补充。作用域包含用户、渠道、发信人和机器人账号，最长等待15分钟。普通历史跳过这些问答，避免取消或过期后从较长的聊天历史中恢复。

回答“下周一”会结合原问题继续处理；明确的日期补充在模型不可用时也可走规则查询。其他补充使用原问题和追问历史交给模型继续理解。多课表候选来自后端，支持“第二个”、课表名称或“使用课表 编号”，重新检查课表归属后查询原问题，不把选择确认当成任务完成。

“取消”“算了”“不用了”“不查了”可结束等待；新同步指令、状态查询或独立课程问题结束旧追问。未确认前不会仅凭“好”“第二个”等回复发起同步任务。清空同学课表必须先展示待确认名单，再由下一轮明确确认触发；与人员选择等追问混合时不授予清空权限，模型参数不能自行授权。

课表内容、学校绑定学号、绑定版本或更新时间改变后，原待确认事项失效。机器人账号之间的普通历史和课表选择也独立存储；本次变更使有账号标识的旧渠道历史不再复用。Redis不可用时明确提示用户把补充信息与原问题一起发送，不宣称已经保存。

测试：`tests/test_agent_clarification.py`。本地2026-10-15完整后端回归812通过、54跳过；跳过项包括未开启的数据库集成测试。真实模型表达质量和实际微信多轮对话需要独立验收，离线回归不代表已经通过这些验收。
