# 小程序他人课表（第一版）

首页课表顶部切换“我的课表 / 他人课表”。他人栏可搜索、预览、保存多人、切换人员、选择学期、填写备注、手动更新和移除收藏。默认启动进入我的课表。

收藏跟账号存储于独立的 academic_others 表，以 user_id + student_id 去重；每人保留一个当前选中的学期快照，切换学期后可重新保存。预览不写收藏。他人课表只读，不进入 schedules、身份绑定、学校同步覆盖、恢复备份和助手默认课表选择逻辑。学校查询不完整或过期时拒绝覆盖收藏。

接口均需要登录：

- GET /api/academic/others：当前账号收藏及快照。
- GET /api/academic/students/{student_id}/schedule?term=...&refresh=true：独立查询/预览。
- PUT /api/academic/others：student_id、term、remark，更新此人收藏。
- DELETE /api/academic/others/{student_id}：只移除当前账号对此人的收藏。

数据库通过 Alembic 0023_academic_others 升级；启动建表路径也已补齐。部署需要同步更新后端与小程序。收藏列表本地缓存与当前登录会话匹配后才可离线回显；更换登录会话时重新从服务端获取。

验证：node --test miniapp/tests/*.test.cjs；node miniapp/scripts/check_wxml.js；在 server 下运行 python -m pytest tests/test_academic_others.py tests/test_academic_binding.py。

尚需在微信开发者工具和真实学校连接下进行真机查询联调。小程序界面暂不提供多人课表叠加或自动后台同步；助手支持按已保存快照比对共同空闲。

## 查询可靠性和账号数据规则

助手的他人课程按人员分组生成，共同空闲按各参与者节次的交集生成；不采用模型自由生成的忙闲结论。缺少参与者课表时不返回部分人员的共同空闲。结果保留学期和快照更新时间，反映保存的课表而非实时行程。

添加同名学生时，候选 ID、班级和公开显示学号保存在当前渠道的短期追问状态中，回复“第2位”、班级或公开学号即可确认。目录支持空格分隔的组合关键词，以及“24级软件1班张三”形式；学号搜索以学校实际公开的字段为准，不恢复被遮盖的数字。

账号关联时，同一学生采用更新时间较新的快照。解绑时，他人课表收藏整体随微信账号迁移，App 账号不留副本；因此解绑期间的更新、删除在重新绑定后仍然保留。该策略适用于他人课表收藏，个人课程继续使用原有复制保全策略。

他人课表预览和保存每用户每分钟最多10次，每账号最多保存50位同学；已有收藏仍可更新。省略备注会保留旧备注，显式传空字符串表示清空。缓存失败不改变服务端保存或删除的成功结果。

已保存收藏的刷新使用 `POST /api/academic/others/{student_id}/refresh`，在学校查询结束后核验原记录的学期和更新时间，只更新快照，不写备注、不重新插入已删除的收藏；遇到并发修改则返回 `saved_person_changed`。

此前退役列表中的 `GET /api/academic/students/{student_id}/schedule` 现在作为登录后的只读预览接口恢复，不能写入个人 schedules、身份绑定或学校同步配置。小程序与后端需同步升级，避免客户端调用新接口时返回404。
