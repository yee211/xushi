# 小程序同学课表（第一版）

首页课表顶部切换“我的课表 / 同学课表”。他人栏可搜索、预览、保存多人、切换人员、选择学期、填写备注、手动更新和移除收藏。默认启动进入我的课表。

助手也支持按姓名、备注或学号移除已保存同学，目标为空时必须追问；同名候选由用户选择。清空全部同学课表需先展示名单，在当前渠道的下一轮明确确认后执行，并核对人数和人员 ID；待确认状态过期或收藏变化后失效。候选列表只展示序号、姓名、年级和班级，不展示脱敏学号，仍支持输入完整学号定位。

收藏跟账号存储于独立的 academic_others 表，以 user_id + student_id 去重；每人保留一个当前选中的学期快照，切换学期后可重新保存。预览不写收藏。同学课表只读，不进入 schedules、身份绑定、学校同步覆盖、恢复备份和助手默认课表选择逻辑。学校查询不完整或过期时拒绝覆盖收藏。

接口均需要登录：

- GET /api/academic/others：当前账号收藏及快照。
- GET /api/academic/students/{student_id}/schedule?term=...&refresh=true：独立查询/预览。
- PUT /api/academic/others：student_id、term、remark，更新此人收藏。
- DELETE /api/academic/others/{student_id}：只移除当前账号对此人的收藏。

数据库通过 Alembic 0023_academic_others 升级；启动建表路径也已补齐。部署需要同步更新后端与小程序。收藏列表本地缓存与当前登录会话匹配后才可离线回显；更换登录会话时重新从服务端获取。

验证：node --test miniapp/tests/*.test.cjs；node miniapp/scripts/check_wxml.js；在 server 下运行 python -m pytest tests/test_academic_others.py tests/test_academic_binding.py。

尚需在微信开发者工具和真实学校连接下进行真机查询联调。小程序界面暂不提供多人课表叠加；助手支持按已保存快照比对共同空闲。

“我的 → 同学课表”始终进入管理页，展示已保存人员并保留搜索添加入口。点击名单选择管理，点击“查看”返回首页展示对应课表。

首页同学课表的“更新”菜单提供更新当前课表和同步全部已保存课表。批量同步通过 `POST /api/academic/others/sync/tasks` 创建持久任务，`GET /api/academic/others/sync/tasks/latest` 恢复进度；提交 `retry_of` 可只重试失败人员。离开页面后服务端继续处理，单人失败不阻断其他人员，失败保留旧快照，期间被删除或修改的收藏跳过。每人按已保存学期刷新，不改备注。任务 15 分钟无进展会被标记失败并释放用户，允许重新发起；完成/失败任务保留 30 天。需要启用现有 `ACADEMIC_SYNC_WORKER_ENABLED` 工作线程并升级数据库至 `0024_other_sync_jobs`。

## 查询可靠性和账号数据规则

助手的同学课程按人员分组生成，共同空闲按各参与者节次的交集生成；不采用模型自由生成的忙闲结论。缺少参与者课表时不返回部分人员的共同空闲。结果保留学期和快照更新时间，反映保存的课表而非实时行程。“我们/咱们”单独出现时默认按用户自己处理；只有同时带“都、一起、共同、谁”等多人语义且已保存同学时才进入共同空闲比对。

助手支持“某某下周有什么课和我不一样”：按目标自然周的周一至周日比较双方课程，日期、课程名、时间、教师和教室相同视为同一安排，数据库课程 ID 不参与比较。分别列出双方不同课程，无差异时明确告知；任一天缺少可用课表或同学身份不明确时返回错误或追问，不输出部分周的比较结论。比较正文由服务端生成，依据同学已保存快照和用户当前有效课表。

添加同名学生时，候选 ID、班级和公开显示学号保存在当前渠道的短期追问状态中，回复“第2位”、班级或公开学号即可确认。目录支持空格分隔的组合关键词，以及“24级软件1班张三”形式；学号搜索以学校实际公开的字段为准，不恢复被遮盖的数字。

账号关联时，同一学生采用更新时间较新的快照。解绑时，同学课表收藏整体随微信账号迁移，App 账号不留副本；因此解绑期间的更新、删除在重新绑定后仍然保留。该策略适用于同学课表收藏，个人课程继续使用原有复制保全策略。

同学课表预览和保存每用户每分钟最多10次，每账号最多保存50位同学；已有收藏仍可更新。省略备注会保留旧备注，显式传空字符串表示清空。缓存失败不改变服务端保存或删除的成功结果。

已保存收藏的刷新使用 `POST /api/academic/others/{student_id}/refresh`，在学校查询结束后核验原记录的学期和更新时间，只更新快照，不写备注、不重新插入已删除的收藏；遇到并发修改则返回 `saved_person_changed`。

此前退役列表中的 `GET /api/academic/students/{student_id}/schedule` 现在作为登录后的只读预览接口恢复，不能写入个人 schedules、身份绑定或学校同步配置。小程序与后端需同步升级，避免客户端调用新接口时返回404。
