# 学校绑定与自动同步

小程序和 Android 使用同一用户账号、学校关联和课表。合并账号会迁移学校关联；两边关联不同学生时，用户选择保留 App 或微信的学校身份，并明确确认另一份绑定和课表被覆盖。确认后清理未选课表，保留所选身份最近已同步的学校主课表并排队刷新；所选身份没有学校课表时清空旧课表、等待首次同步。冲突版本发生变化会要求重新确认，取消时不修改数据。

## 用户流程

从“课表中心”选择“绑定学校身份”，搜索并关联自己的学校信息，选择学期并点击“同步并覆盖课表”。这里只关联学校目录信息，不代表身份认证。

同步请求立即返回任务，客户端每 1.5 秒查看进度。关闭页面不会停止服务端任务；重新打开可恢复进度，之前手动提交的任务完成后会加载结果。同一账号重复提交同一任务会复用任务；已有任务时不能切换学期启动另一任务。

学校返回完整且有效的课表后，在一个数据库事务中覆盖现有主课表并清理该账号其他课表，包括导入内容和个人修改。旧课表 ID 尽量保留。同步失败、返回不完整数据或绑定已改变时保留原课表。学校确认某学期没有课程时可以覆盖为空课表。

## 并发和缓存

任务保存在 PostgreSQL，数据库会选出一个学校同步执行器，多 API 进程也串行处理。重启后重新处理未完成任务，写入过程幂等。暂时性限流、连接故障最多尝试 3 次，间隔为 20、40 秒。学校认证过期时后续队列暂停 60 秒再检查，管理员应恢复学校登录，已失败任务需重新提交。

学校 HTTP 请求通过 Redis 原子限流，每秒至多一个请求。Redis 已配置但故障时拒绝继续访问学校，避免多进程绕过限制；未配置 Redis 时单进程采用本地限流。多进程部署应配置统一 REDIS_URL 或 AGENT_REDIS_URL。

客户端读取自己的课表走 Redis 缓存，未命中回查 PostgreSQL。数据库是持久化数据源；成功写入后切换缓存版本，避免旧请求重新写回有效缓存。Redis 故障不影响已存课表读取。

任务记录仅保留结果摘要，不保存旧课表课程副本，30 天后清理。

## 零点同步

服务运行时每天北京时间（Asia/Shanghai）00:00 生成当日批次，对全部已关联账号排队同步，不会在零点同时向学校发请求。任务依次完成，完成时间取决于账号数量、学校速度和登录状态。

使用上次成功同步的学期；尚未同步的账号使用绑定时的默认学期。切换学期后先手动同步一次，之后每日更新该学期。首次启动或当天零点停机后启动，会补发当天尚未生成的批次；不补发过去多天的旧批次。

必须让后端持续运行。默认 ACADEMIC_SYNC_WORKER_ENABLED=true；关闭时 API 仍可创建和查询任务，但不会消费队列或生成每日批次。队列选择通过 PostgreSQL 会话锁实现，不适用于事务模式 PgBouncer。

## 接口与运维

- POST /api/academic/binding/sync/tasks：提交任务，返回 HTTP 202。
- GET /api/academic/binding/sync/tasks/latest：查询当前账号最近任务。
- GET /api/academic/binding/sync/tasks/{id}：仅允许所属账号查询。
- GET /api/admin/academic/sync/status：管理员查看队列统计、最近批次和暂停时间。

管理后台学校连接页展示队列进度。两端统一走任务队列；旧直接同步接口已移除。迁移 0013_academic_sync_jobs 新建任务与批次表；应用启动也会幂等创建。

## 验证

普通回归：server/venv/Scripts/python.exe -m pytest server/tests -q。

数据库队列集成测试：设置 TEST_ACADEMIC_QUEUE_DB=1 后运行 test_academic_jobs.py。每个测试创建独立临时 schema，结束后移除；学校查询用模拟结果，不读取真实学校课表。覆盖去重、账号隔离、单执行器、重启恢复、零点批次、绑定变更、有限重试和登录过期暂停。

## 整学期获取优化

优先使用明确单页、非空、字段可解析且课程周次符合校历的整学期报表。课表获取本身需要校历、报表地址、报表三次请求，外层另有一次学期检查。报表分页、空白、无法完整解析、缺少单页标记或周次异常时退回逐周核验。空课表仍须核验全部周次，不能凭空报表覆盖已有课表。
