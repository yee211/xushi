# 备份与恢复验证

默认 Compose 的 db-backup 每次生成一个 xushi_bundle_UTC时间 目录，包含 PostgreSQL 自定义格式备份、
持久 data 目录归档、SHA256 校验和及完成时间。写入临时目录并验证后才发布为完整备份。
成功后间隔 24 小时；失败 5 分钟后重试；清理超过 14 天的完整新格式备份，保留旧格式 dump。

文件归档包括学校加密配置、持久密钥和其他 data 文件；排除浏览器 profile、学校查询 SQLite 缓存、
登录截图、临时文件和 .env。目录权限按 0700、文件按 0600 创建。备份中仍有敏感配置，应限制访问。
配置归档与数据库 dump 不构成同一事务的快照；恢复学校连接后须验证，必要时重新登录。

ACADEMIC_CREDENTIAL_SECRET、JWT_SECRET、微信加密密钥等环境变量不在 data 归档中。
须在独立的安全位置保存部署密钥及 Compose 配置，才能解密对应备份；不要把明文 .env 放进备份目录。
默认仅保存在当前主机，仍应由运维将完整备份复制到独立存储。

## 恢复演练

在部署目录执行下面命令，将实际备份目录名替换进去：

    docker compose exec db-backup /bin/sh /scripts/verify-backup.sh /backups/xushi_bundle_20261011T000000Z

脚本先验证校验和与归档，然后新建 xushi_restore_check_ 前缀的临时数据库，
通过 pg_restore --exit-on-error 恢复并检查核心表，退出时删除该临时数据库。
不向应用数据库恢复，不输出用户数据。需要创建数据库权限及足够的磁盘空间。
运行成功才能确认数据库备份可恢复；自动备份本身只验证归档结构与校验和。
如进程被强杀导致临时数据库残留，应先核对名称再手动清理。

## 正式恢复

正式恢复前停止业务写入并保存当前数据库与 data 的备份。选择已通过演练的同一 bundle，
恢复 PostgreSQL 与所需 data 文件，配置对应环境变量密钥，再启动并验证登录、课表及学校连接。
浏览器 profile 和缓存无需恢复。正式覆盖操作应单独安排，不能直接套用演练脚本。
